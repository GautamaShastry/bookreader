# Coding Agent Instructions for BookScope AI

Read `00-START-HERE.md` before editing source code. Product and security requirements in the spec set are authoritative; this file translates them into coding rules.

## Non-negotiable behavior

1. Never answer from a model's general knowledge; generate answers only after verified same-book evidence and a passing verifier. No external search.
2. Never trust `owner_id`, `book_version_id`, citation IDs or selection text in client input. Resolve identity server-side and verify all source maps.
3. Treat document content as untrusted data, never as system instructions; guard against decompression bombs and content injection.
4. Do not stream model drafts until the evidence/citation check has passed.
5. Implement source location resolution and canonical hash validation before polishing chat UX.
6. Never claim a benchmark win, deployment, security guarantee, or resume metric without captured test evidence.

## Development workflow

- Choose the next ticket in `09-DELIVERY-PLAN.md` in dependency order.
- Read the acceptance IDs in `02-FUNCTIONAL-REQUIREMENTS.md` and `08-EVALUATION-AND-TESTING.md`.
- Write failing unit/integration tests for that behavior.
- Implement the smallest cohesive change that passes them.
- Run formatting, type checks, unit tests, contract/schema validation, and relevant smoke checks.
- Record results in the PR description: what was implemented, tested, not tested, AWS cost impact, and edge cases.
- Update specs/ADRs when requirements evolve; do not silently redefine product behavior.

## Multi-agent implementation rules (v1.1)

1. Use one bounded LangGraph graph in `/services/agent-runtime/` with five logical roles; invoke only required specialists per request.
2. All handoffs conform to `schemas/agent-contract.schema.json`; validate inputs/outputs using Pydantic/JSON Schema, and never use untyped raw-message handoffs as authoritative data.
3. No agent can modify `owner_id`, `book_id` or `book_version_id`. These come from an authorized backend scope object and are rechecked on every tool read.
4. Supervisor sees only the current task, a compact TOC and resolved referents; no whole book. Retriever cannot fetch outside scoped knowledge. Teacher sees only canonical validated evidence. Summary workers see one block each. Verifier sees claims + original source excerpts but not teaching rationale.
5. No unverified answer streams. Respect max 2 retrieval passes, 1 repair and per-role model token/time budgets. Summary section workers may run concurrently only within configured limits; reduction must preserve chapter order and coverage.
6. The public API is Lambda/FastAPI; AgentCore Runtime is orchestration, not a duplicate API. Tests must run graph locally with fake model and KB adapters before cloud deployment.
7. Run single-agent vs multi-agent ablation before making resume performance claims. Record error cases and AWS usage/cost by logical agent.

## v1.3 coding agent guardrails

- Opening a book must never cause automatic fresh LLM inference. Implement `BOOK_OPENED -> authorized cached brief GET -> verified panel` with safe pending/partial/failure fallbacks.
- The brief must be generated by an idempotent async job after indexing READY, with a complete chapter ledger and canonical source citation verification before publication.
- Deliver stage-level tests with every PR: parser, chunker, retrieval, routing, teaching, summarization, verifier, publisher and React book-open UX as applicable. All critical security/citation tests block merge.
- Do not invent performance/evaluation results, general book facts, unseen chapter contents or whole-book completeness claims.
- Do not add auto-interception of arbitrary OS/browser books without a new permissions/privacy/design review.


## v1.4 mandatory coding-agent rules

Read `15-DECISION-FREEZE-AND-DEVELOPMENT-CONTRACT.md` and `16-FIRST-CODING-AGENT-TICKETS.md` before accepting work. Full-book summary is first-release scope, **explicitly user-triggered**, and must traverse every chapter from the canonical manifest (no top-k-only summary). `BOOK_OPENED` never starts fresh LLM work. App-level AWS target `$50/month`, no paid AWS deployment without approval, default per-full-book model estimate ceiling `$2.50`; reject rather than silently truncate. Every PR delivers stage-specific deterministic and adversarial eval evidence.
